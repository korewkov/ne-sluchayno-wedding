# Netlify

Исходное состояние сохранено Git-тегом `before-netlify-2026-10-20`.

Сборка: `npm ci`, `npm run check`, `npm run build`. Публикуемый каталог — `dist/public_html`; конфигурация — `netlify.toml`. PHP-файлы в публикацию Netlify не входят.

Серверные функции сохраняют данные в Netlify Blobs. Это хранилище сайта, данные переживают новую публикацию. Предпросмотры должны использовать отдельное имя хранилища и отдельные секреты, чтобы не менять настоящие ответы.

Без персональной ссылки открывается только сообщение о доступе. Токен передаётся во фрагменте `#i=…`, затем хранится в sessionStorage текущей вкладки и удаляется из адресной строки; API получает его в Authorization. Не пересылайте персональные ссылки другим людям.

Фотографии и исходный текст уже находятся в публичном GitHub-репозитории. Ограничение входа на сайт не делает опубликованный ранее репозиторий приватным и не является защитой прямых адресов статических файлов.

После публикации проверить: вход и выход организатора, создание ссылки, анкеты взрослых/детей, +1, повторное сохранение и перезагрузку, пожелания, отзыв ссылки, запрет анонимного доступа к API. Ответы гостей не помещать в Git. Перед массовыми правками или удалением приглашений скачать экспорт из кабинета.

Доступность по HTTPS из одного подключения не подтверждает доступность из всех сетей России. Перед рассылкой проверить с домашнего и мобильного интернета без VPN.

## Секреты кабинета

`node scripts/netlify-secrets.mjs` один раз создаёт `.local/netlify.env` и `.local/netlify-admin.txt` с правами 600. Первый файл импортировать в переменные окружения Netlify (секреты для Functions), второй содержит пароль владельца для `/admin`. Значения в репозиторий не попадают. Существующие файлы скрипт не заменяет.

Нужны `WEDDING_ADMIN_PASSWORD_HASH` (scrypt), `WEDDING_SESSION_SECRET` (случайные 32+ символа), `WEDDING_PUBLIC_URL` (основной HTTPS адрес; при отсутствии используется Netlify `URL`). Для production хранилище `wedding-private-v1`; для preview отдельное `wedding-private-preview-<DEPLOY_ID>`. Не переименовывать production хранилище после начала приёма ответов.

Проверки: `node --test tests/backend.test.mjs`. Тесты используют только память и вымышленные данные. Тестовый API запускается `node tests/backend-preview.mjs`, затем `npm run dev`; он теряет данные при остановке, для публикации не используется.

Ключи повторных запросов предотвращают дубли пожеланий и создания приглашений при временном сбое сети. После сохранения анкеты сервер возвращает актуальный состав, включая постоянный ID спутника.
